# Minecraft 26.3 port

Build with a complete Java 25 JDK and the checked-in Gradle 9.5.1 wrapper:

```sh
bash gradlew clean build
bash gradlew -PgameTests -PacceptMinecraftEula=true runGameTest
```

Only pass `acceptMinecraftEula=true` if you accept the Minecraft EULA.
GameTests use a disposable world under `build/run/gameTest`. Never run reset
verification against a world you want to keep.

## Baseline repair

The starting `port/26.2` commit referenced MinecraftServerAccessor,
ServerLevelAccessor, and PlayerAccessor in Java and the Mixin configuration,
but did not contain their source files. Restoring the three accessor interfaces
made the 26.2 build pass before changing Minecraft versions. This failure was
not introduced by 26.3. The accessed fields and their types exist in both versions.
The worldGenSettings setter is mutable because Minecraft declares the field final.

## Versions

- Minecraft 26.3
- Fabric API 0.166.0+26.3
- Fabric Loader 0.19.5
- Fabric Loom 1.17.20
- Java 25; Gradle wrapper 9.5.1

## Validation

- Clean 26.3 build passed.
- GameTests passed, exercising server storage/executor/dimension/spawner access,
  the world generation settings setter, the player food accessor, and inventory,
  ender chest, experience, and hunger reset behavior.
- A disposable dedicated server loaded all four dimensions, including limbo.
- Scheduled resets without connected players completed with seed reuse enabled
  and disabled; the attempt counter advanced, the timer restarted, and saving
  and shutdown completed successfully.

These checks do not establish graphical client compatibility, authenticated
multiplayer behavior, player death-to-limbo round trips, offline-player rescue,
or optional Trinkets compatibility. Those still require gameplay testing.
